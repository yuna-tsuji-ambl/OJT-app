# 日次・週次報告書機能 テスト仕様書

## 概要

新卒が日次・週次の振り返りをテンプレートに沿って記録し、トレーナーが一覧・詳細を閲覧する機能。コンディション（§7.2）とは別に、**文章ベースの業務報告**を担う。

**仕様の正**: `docs/detailed-design.md` §7.5、§6.1、§8.6.2、§9（`reports` コレクション）  
※画面導線は本仕様書の「画面・導線」を優先する（下記変更を反映）。

### 入力項目定義（§7.5.4 ドメインモデル）

#### 日次（`DailyReportContent`）

| 内部キー       | 画面表示名（想定） | 型     |
| -------------- | ------------------ | ------ |
| `doneToday`    | 本日やったこと     | string |
| `learnedToday` | 学んだこと         | string |
| `blockers`     | 困っていること     | string |
| `planTomorrow` | 明日やること       | string |

#### 週次（`WeeklyReportContent`）

| 内部キー              | 画面表示名（想定） | 型     |
| --------------------- | ------------------ | ------ |
| `achievements`        | 今週の成果         | string |
| `nextWeekGoals`       | 来週の目標         | string |
| `reflection`          | 所感               | string |
| `questionsForTrainer` | トレーナーへの相談 | string |

#### 報告エンティティ（`Report`）

| フィールド    | 型                       | 説明                                     |
| ------------- | ------------------------ | ---------------------------------------- |
| `id`          | string                   | 報告 ID                                  |
| `traineeId`   | string                   | 新卒 ID                                  |
| `type`        | `'daily' \| 'weekly'`    | 報告種別                                 |
| `periodKey`   | string                   | `YYYY-MM-DD` または `YYYY-Www`（ISO 週） |
| `content`     | `DailyReportContent` 等  | 報告本文                                 |
| `status`      | `'draft' \| 'submitted'` | 下書き / 提出済み                        |
| `submittedAt` | string（任意）           | 提出日時（`submitted` 時）               |
| `createdAt`   | string                   | 作成日時                                 |
| `updatedAt`   | string                   | 更新日時                                 |

### 業務ルール（詳細設計より）

| ルール ID | 内容                                                                                                                                                                               |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BR-R01    | 日次報告は 1 日 1 件（`periodKey` = `YYYY-MM-DD`。上書き更新）                                                                                                                     |
| BR-R02    | 週次報告は 1 週 1 件（`periodKey` = `YYYY-Www`（ISO 週）。上書き更新）                                                                                                             |
| BR-R03    | 日次報告は下書き保存（`draft`）と提出（`submitted`）の両方をサポート（UC-R01）                                                                                                     |
| BR-R04    | 週次報告は作成・提出が可能（UC-R02）                                                                                                                                               |
| BR-R05    | 新卒は過去の自分の報告を別 URL の一覧で閲覧でき、本文全体の検索および期間絞り込み（`from`/`to` または `date`）ができる（UC-R03）                                                   |
| BR-R06    | トレーナーは担当新卒の報告一覧を未読・最新順で閲覧できる（UC-R04）                                                                                                                 |
| BR-R07    | 新卒はヘッダー「報告書」から `/reports` へ遷移する（日次・週次入力を同一ページに配置）                                                                                             |
| BR-R08    | トレーナーはヘッダー「報告書」から `/reports` へ遷移し、担当新卒の報告書一覧を表示する（従来ダッシュボード「報告書一覧」と同等）。ダッシュボード上の「報告書一覧」リンクは置かない |
| BR-R09    | 新卒の `/reports` では、上から日次入力欄 → 日次一覧リンク → 週次入力欄 → 週次一覧リンクの順で配置する                                                                              |
| BR-R10    | 日次/週次の入力は `/reports` に集約する。旧パス `/reports/daily`・`/reports/weekly` への直接アクセスは `/reports` へリダイレクトする                                               |
| BR-R11    | 日次報告書一覧は `/reports/daily/list`、週次報告書一覧は `/reports/weekly/list` とする（パス案 A）                                                                                 |
| BR-R12    | 一覧検索は報告本文（`content` の全テキストフィールド）を対象とする。`periodKey` は検索対象に含めない                                                                               |
| BR-R13    | 一覧の期間絞り込みは、範囲指定（`from` / `to`）または特定指定（`date`）のいずれか一方のみとする                                                                                    |
| BR-R14    | 日次の `from`/`to`/`date` は `YYYY-MM-DD`。週次の `from`/`to`/`date` は `YYYY-MM-DD`（その日を含む ISO 週）と `YYYY-Www`（週キー）の両方を受け付ける                               |
| BR-R15    | `from`/`to` と `date` を同時指定した場合は HTTP 400（API）および画面上で「期間の範囲指定と特定日は同時に使えません。どちらか一方だけを指定してください。」を返し、一覧は更新しない |

### API エンドポイント（§8.6.2）

| メソッド | パス                           | ロール           | 説明                                                                                                                         |
| -------- | ------------------------------ | ---------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| GET      | `/api/reports/daily`           | trainee          | 自分の過去日次報告一覧。`q`=本文全体検索。期間は `from`/`to` または `date`（`YYYY-MM-DD`）。同時指定は 400                   |
| GET      | `/api/reports/daily/:date`     | trainee          | 指定日の日次報告取得                                                                                                         |
| PUT      | `/api/reports/daily/:date`     | trainee          | 日次報告の保存・提出                                                                                                         |
| GET      | `/api/reports/weekly`          | trainee          | 自分の過去週次報告一覧。`q`=本文全体検索。期間は `from`/`to` または `date`（`YYYY-MM-DD` または `YYYY-Www`）。同時指定は 400 |
| GET      | `/api/reports/weekly/:weekKey` | trainee          | 指定週の週次報告取得                                                                                                         |
| PUT      | `/api/reports/weekly/:weekKey` | trainee          | 週次報告の保存・提出                                                                                                         |
| GET      | `/api/reports`                 | trainer          | 報告一覧（`?traineeId=&type=`）                                                                                              |
| GET      | `/api/reports/:id`             | trainer, trainee | 報告詳細                                                                                                                     |

### スコープ外（Phase 2）

詳細設計 §7.5.3 UC-R05 に基づき、**トレーナーによる報告へのコメント**は Phase 2（任意）とする。本仕様書の Phase 3 テスト対象外。将来テストは末尾「Phase 2 予定テスト」に記載。

## ※確認事項

詳細設計を正としたうえで、設計書内に明記のない実装判断が必要な点。

1. **必須項目の範囲**: 提出（`submitted`）時に `DailyReportContent` / `WeeklyReportContent` の全フィールドが必須か、一部任意か。
2. **テキスト項目の最大文字数**: 各 `string` フィールドの上限文字数（ドメイン層バリデーション値）。
3. **未作成報告の GET レスポンス**: `GET /api/reports/daily/:date` 等で報告未作成時に HTTP 200（空）とするか 404 とするか。
4. **下書き時の部分入力**: `draft` 保存時に空フィールドを許可するか（本仕様書 U-R25 は許可を想定）。
5. **週次の下書き**: UC-R02 は「作成・提出」のみ記載。週次も `draft` をサポートするか。
6. **「未読」の定義**: UC-R04 の未読判定条件（トレーナーが詳細を初回閲覧した時点で既読とするか等）。
7. **担当外新卒の認可**: 担当外の `traineeId` 指定時に HTTP 403 とするか、空一覧を返すか。
