# 質問・メッセージ機能 テスト仕様書

## 概要

新卒がホーム画面（`/home`）からトレーナーへ質問・メッセージを送信し、トレーナーがメッセージ画面（`/messages`）で受信・返信する機能。テンプレート選択と自由記述の両方に対応する。

**チャットルームモデル**: メッセージを送信するたびに **チャットルーム**（API 上は `MessageThread` / `threadId`）が作成される。ホームには参加中のチャットルームが **新しい順** に一覧表示され、ルームを開くと **LINE 風** の時系列 UI でやり取りできる。スタンプは **Slack 風** に入力欄付近へ横並び配置し、トレーナー・新卒の双方が利用できる（新卒用は **敬語** 表現）。

**関連機能**: トレーナーステータス表示（質問OK / 集中モード）は [status-feature.md](./status-feature.md)（U-S01〜U-S02）を参照。本仕様書は **メッセージ送受信・チャットルーム・テンプレート・スタンプ・リアルタイム更新** を対象とする。

> **レガシー廃止**: 旧「後で話そう」ボタン（`ReplyStampBar` / フラット `ChatMessage` 返信）は **提供しない**。関連テスト（status 仕様書 U-S04 の簡易返信例）は本仕様書のスタンプ・チャットルーム系テストへ移行する。

### UI 要件（チャットルーム・スタンプ配置）

#### ホームのチャットルーム一覧（新卒 `/home`）

| 項目       | 要件                                                               |
| ---------- | ------------------------------------------------------------------ |
| 一覧の場所 | ホーム画面上部または送信フォーム直下（実装詳細は詳細設計書で確定） |
| 1 件の表示 | 先頭メッセージのプレビュー、または相手名＋最新メッセージ要約       |
| 並び順     | **最新の `updatedAt` 降順**（新しいルームが上）                    |
| 新規送信時 | 新規ルームが一覧に追加され、通常は先頭に表示される                 |
| 操作       | ルームをタップ／クリックで **LINE 風チャット画面**（ルーム詳細）へ |

#### LINE 風チャットルーム（ルーム詳細）

| 項目             | 要件                                                              |
| ---------------- | ----------------------------------------------------------------- |
| メッセージ表示   | 時系列（古い→新しい）で縦スクロール。送信者ごとに吹き出し等で区別 |
| 入力             | テンプレート／自由記述／送信ボタン（役割に応じた組み合わせ）      |
| 履歴             | 同一 `threadId` のメッセージが欠落なく表示される                  |
| アクセシビリティ | メッセージ履歴は `role="log"` 等でスクリーンリーダー対応          |

#### Slack 風スタンプバー

| 項目       | 要件                                                              |
| ---------- | ----------------------------------------------------------------- |
| 配置       | メッセージ入力欄の **直下または直上** に **横並び**（折り返し可） |
| 対象画面   | チャットルーム詳細（新卒・トレーナー双方）                        |
| トレーナー | ST1〜ST5 を表示。`aria-label` またはボタン名で E2E 特定可能       |
| 新卒       | STS1〜STS5（敬語）を表示                                          |
| 非表示     | レガシー「後で話そう」単独ボタンは **含めない**                   |

> **注**: E2E では `getByRole('button', { name: '...' })` で一意に特定できるラベルを正とする。スタンプバー領域には `role="region"` と `aria-label`（例: `スタンプ返信`）を付与する。

### ドメインモデル（目標）

```typescript
interface MessageThread {
  id: string;
  traineeId: string;
  trainerId: string;
  createdAt: string;
  updatedAt: string;
}

interface ThreadChatMessage {
  id: string;
  threadId: string;
  senderId: string;
  receiverId: string;
  content: string;
  type: 'text' | 'template' | 'stamp';
  templateId?: string; // type が template の場合
  stampId?: string; // type が stamp の場合（ST* / STS*）
  createdAt: string;
}
```

**チャットルーム作成ルール**

- 新卒またはトレーナーが **新規メッセージ**（`threadId` 未指定）を送信したとき、新しい `MessageThread`（チャットルーム）を作成し、先頭メッセージを紐づける。
- 既存ルームへの **返信** は `threadId` を指定してメッセージを追加する。**新規ルームは作成しない**。
- 一覧 API は **最新メッセージ時刻（`updatedAt`）降順** で返す。
