# 質問・メッセージ機能 テスト仕様書

## 概要

新卒がホーム画面（`/home`）からトレーナーへ質問・メッセージを送信し、トレーナーがメッセージ画面（`/messages`）で受信・返信する機能。テンプレート選択と自由記述の両方に対応する。

**チャットルームモデル**: メッセージを送信するたびに **チャットルーム**（API 上は `MessageThread` / `threadId`）が作成される。ホームには参加中のチャットルームが **新しい順** に一覧表示され、各ルームには **最終やり取り日時** が表示される。ルームを開くと **LINE 風** の時系列 UI（自分は右寄せ・相手は左寄せ、送信者名付き吹き出し）でやり取りでき、**開封時の視点はチャット欄の最下部（最新メッセージ）に固定** される。スタンプは **Slack 風** に入力欄付近へ横並び配置し、トレーナー・新卒の双方が利用できる（新卒用は **敬語** 表現）。

**関連機能**: トレーナーステータス表示（質問OK / 集中モード）は [status-feature.md](./status-feature.md)（U-S01〜U-S02）を参照。本仕様書は **メッセージ送受信・チャットルーム・テンプレート・スタンプ・リアルタイム更新** を対象とする。

> **レガシー廃止**: 旧「後で話そう」ボタン（`ReplyStampBar` / フラット `ChatMessage` 返信）は **提供しない**。関連テスト（status 仕様書 U-S04 の簡易返信例）は本仕様書のスタンプ・チャットルーム系テストへ移行する。

### UI 要件（チャットルーム・スタンプ配置）

#### ホームのチャットルーム一覧（新卒 `/home`・トレーナー `/messages`）

| 項目             | 要件                                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 一覧の場所       | ホーム画面上部または送信フォーム直下（実装詳細は詳細設計書で確定）                                                                     |
| 1 件の表示       | 先頭メッセージのプレビュー（または要約）と **最終やり取り日時**                                                                        |
| 日時の表示       | `MessageThread.updatedAt` を **`YYYY年M月D日 H:mm`** 形式で表示（例: `2026年7月23日 14:30`）。タイムゾーンはクライアントのローカル時刻 |
| 日時の意味       | 当該ルームにおける **直近メッセージの送信時刻**（新規送信・返信のいずれも更新）                                                        |
| 並び順           | **最新の `updatedAt` 降順**（新しいルームが上）                                                                                        |
| ページング       | 一覧は **20 件ずつ** 表示（段階読込。境界テストは 20 件単位）                                                                          |
| 新規送信時       | 新規ルームが一覧に追加され、通常は先頭に表示される                                                                                     |
| 操作             | ルーム行をクリックで **当該行の直下** にチャット欄（ルーム詳細）を **インライン展開**する。同一ルーム再クリックで **閉じる**           |
| 選択状態         | 選択中のルーム行は **背景色等で色分け** し、未選択行と区別できる                                                                       |
| 空状態           | ルーム **0 件** のときは空状態テキストのみ表示し、チャット欄は開かない                                                                 |
| アクセシビリティ | 各ルーム行は `article` 等で識別可能とし、日時は `time` 要素の `datetime`（ISO 8601）または同等の機械可読属性を付与する                 |

#### LINE 風チャットルーム（ルーム詳細）

| 項目               | 要件                                                                                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| メッセージ表示     | 時系列（古い→新しい）で縦スクロール。送信者ごとに吹き出し等で区別                                                                                                                          |
| 送信者の判別       | **自分のメッセージは右寄せ**、**相手のメッセージは左寄せ** とする（LINE と同様）                                                                                                           |
| 送信者名           | 各吹き出しの近傍に送信者を示すラベルを表示する。新卒画面では自分を「あなた」、相手を「トレーナー」。トレーナー画面では自分を「あなた」、相手を「新卒」（表示名は詳細設計書で確定可）       |
| スタンプ・テンプレ | テキストと同様に左右寄せ・送信者名のルールを適用する                                                                                                                                       |
| 入力               | テンプレート／自由記述／送信ボタン（役割に応じた組み合わせ）                                                                                                                               |
| 履歴               | 同一 `threadId` のメッセージが欠落なく表示される                                                                                                                                           |
| スクロール位置     | ルームを開いた直後は **履歴の最下部**（最新メッセージ）が表示範囲内に入ること。ユーザーが手動で上へスクロールしない限り、新着・送信後も **下端を基準とした視点** を維持する（LINE と同様） |
| アクセシビリティ   | メッセージ履歴は `role="log"`。各吹き出しは送信者名を含む `aria-label` または関連付けられたラベルで E2E・スクリーンリーダー対応する                                                        |

> **E2E 向けの目安**: 自分の吹き出しには `data-sender="self"`、相手には `data-sender="other"` 等の安定した属性、または送信者名テキストで `getByRole('article', { name: /トレーナー:/ })` のように特定できること。

> **E2E 向けの目安（スクロール）**: 履歴コンテナ（`role="log"`）の `scrollTop + clientHeight` が `scrollHeight` と一致する、または最後の吹き出しが表示範囲内であることで「下端固定」を検証できること。

#### メッセージスレッド一覧からのインライン展開（R-M17）

| 項目                 | 要件                                                                                                                                           |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 対象画面             | 新卒 `/home`、トレーナー `/messages`（**同一仕様**）                                                                                           |
| 展開位置             | クリックしたルーム行（`li` > `article`）の **DOM 直後**（厳密に直下）                                                                          |
| 開くアニメーション   | チャット欄の高さが **0 → 表示高さ** へ増加し、**下端が下方向に伸びる**                                                                         |
| 閉じる操作           | **同一ルーム行を再クリック**                                                                                                                   |
| 閉じるアニメーション | 開くアニメーションの逆（高さ **表示高さ → 0**）。完了後は非表示                                                                                |
| 別ルーム選択         | いったん **閉じアニメーション** の後、新しい行の直下で **開くアニメーション**（2 段階）                                                        |
| 履歴取得失敗         | チャット欄内（または近傍）に **エラーメッセージ** を表示する                                                                                   |
| アクセシビリティ     | ルーム詳細は `role="region"`（例: `スレッド詳細`）。開閉状態を E2E で判定できる属性（例: `data-state="open" \| "closed"`）を付与することを推奨 |

> **E2E 向けの目安（インライン展開）**: 選択 `article` の親 `li` の `nextElementSibling` がチャット欄のルート要素であること。開閉アニメーション中は `getBoundingClientRect().height` の増減で検証できること。固定 `sleep` は使わないこと。

> **注**: `prefers-reduced-motion: reduce` 時の挙動（即時表示等）は **未決定**。決定後に TC-MSG-UI-022 を確定する。

#### Slack 風スタンプバー

| 項目       | 要件                                                              |
| ---------- | ----------------------------------------------------------------- |
| 配置       | メッセージ入力欄の **直下または直上** に **横並び**（折り返し可） |
| 対象画面   | チャットルーム詳細（新卒・トレーナー双方）                        |
| トレーナー | ST1〜ST5 を表示。`aria-label` またはボタン名で E2E 特定可能       |
| 新卒       | STS1〜STS5（敬語）を表示                                          |
| 非表示     | レガシー「後で話そう」単独ボタンは **含めない**                   |

> **注**: E2E では `getByRole('button', { name: '...' })` で一意に特定できるラベルを正とする。スタンプバー領域には `role="region"` と `aria-label`（例: `スタンプ返信`）を付与する。

### ドメインモデル（目標）

```typescript
interface MessageThread {
  id: string;
  traineeId: string;
  trainerId: string;
  createdAt: string;
  updatedAt: string;
}

interface ThreadChatMessage {
  id: string;
  threadId: string;
  senderId: string;
  receiverId: string;
  content: string;
  type: 'text' | 'template' | 'stamp';
  templateId?: string; // type が template の場合
  stampId?: string; // type が stamp の場合（ST* / STS*）
  createdAt: string;
}
```

**チャットルーム作成ルール**

- 新卒またはトレーナーが **新規メッセージ**（`threadId` 未指定）を送信したとき、新しい `MessageThread`（チャットルーム）を作成し、先頭メッセージを紐づける。
- 既存ルームへの **返信** は `threadId` を指定してメッセージを追加する。**新規ルームは作成しない**。
- 一覧 API は **最新メッセージ時刻（`updatedAt`）降順** で返す。
