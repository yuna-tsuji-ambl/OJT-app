# 本番認証（Firebase Auth）テスト仕様書

## 概要

ロール選択式モック認証（F-05）を、**Firebase Auth + Firestore `users`** による本番向け認証（F-10）に置き換える。  
API は ID トークンを検証し、`UserContext { userId, role }` を供給する。担当 N:M は F-11。

**仕様の正**: 本仕様書の「確定事項」および `docs/detailed-design.md` §5.4、§8.1、§9.5（`users`）  
※ステータスは **一部実装**（Vitest 自動化あり。Auth Emulator 実結合 E2E は任意フラグ）。

### 確定事項（レビュー回答・すべておすすめ採用）

| #   | 論点            | 決定                                                                                 |
| --- | --------------- | ------------------------------------------------------------------------------------ |
| 1   | 認証プロバイダ  | **Firebase Auth**                                                                    |
| 2   | API 認証        | 本番パスは **`Authorization: Bearer <ID トークン>` のみ**（`X-User-*` は受理しない） |
| 3   | `userId`        | **Firebase UID をそのまま**使う                                                      |
| 4   | `role` の正本   | **Firestore `users/{uid}.role`**                                                     |
| 5   | `users` 未登録  | 保護 API は **403**（他ユーザーデータは見えない）                                    |
| 6   | ローカル開発    | **Auth Emulator** を主経路。必要なら **`AUTH_MODE=mock` でモック残置**               |
| 7   | Firestore Rules | F-10 で **Auth 必須**を最低限。担当詳細は F-11                                       |
| 8   | 初版ログイン    | **メール/パスワード**（または Emulator ユーザー）。Google ログイン等は対象外         |

### 業務ルール

| ルール ID | 内容                                                                 |
| --------- | -------------------------------------------------------------------- |
| BR-A01    | `AUTH_MODE=firebase` では有効な ID トークンなしの保護 API は 401     |
| BR-A02    | トークンは有効でも `users/{uid}` が無い場合は 403                    |
| BR-A03    | `userId` は Firebase UID。クライアントが別 ID を名乗っても採用しない |
| BR-A04    | `role` は `users.role` のみ。リクエストヘッダーの role は信頼しない  |
| BR-A05    | Bearer と `X-User-*` の混在で権限昇格しない（firebase モード）       |
| BR-A06    | `AUTH_MODE=mock` はローカル/CI 用。本番デプロイでは使わない          |
| BR-A07    | ログイン手段初版はメール/パスワード（Emulator 可）                   |
| BR-A08    | 本機能の自動化対象テストが CI で Pass する                           |

### API・コンテキスト（契約）

| 項目               | 内容                                                      |
| ------------------ | --------------------------------------------------------- |
| 成功時コンテキスト | `{ userId: <uid>, role: 'trainee' \| 'trainer' }`         |
| 401                | トークン欠落・不正・期限切れ（firebase モード）           |
| 403                | トークン有効だが `users` 未登録、またはロール不一致の操作 |
| ヘルスチェック     | `/health` / `/api/health` は従来どおり認証不要            |
