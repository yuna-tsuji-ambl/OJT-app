# 学び共有機能 テスト仕様書

## 概要

新卒が**その日に学んだ内容**と**参考 URL** を投稿し、新卒・トレーナーが**タイムライン**で閲覧する機能（F-09）。  
完了条件: 本仕様書、`LearningPost` API + Firestore、投稿画面 `/learnings/new`、タイムライン `/learnings`、CI 通過。

**仕様の正**: 本仕様書の「確定事項（実装既定）」および `docs/detailed-design.md` §7.7、§6.1、§8.6.4、§9（`learningPosts`）  
※詳細設計と差分がある項目は本仕様の確定事項を優先し、実装時に詳細設計へ同期する。

### 確定事項（実装既定）

仕様書作成時点で完了条件を満たすために採用する既定。曖昧点の残りは末尾「※確認事項」。

| #   | 論点                    | 決定                                                                                             |
| --- | ----------------------- | ------------------------------------------------------------------------------------------------ |
| 1   | 初版スコープ            | `POST`（新卒）・`GET`（新卒/トレーナー）・UI 投稿/タイムライン。**編集・削除・いいねは Phase 2** |
| 2   | 投稿権限                | **新卒のみ** `POST`。トレーナー `POST` は 403                                                    |
| 3   | 閲覧権限                | **新卒・トレーナーとも** タイムラインを閲覧可（`GET /api/learnings`）                            |
| 4   | `title` / `body` 最大長 | **title: 100 文字**、**body: 2000 文字**（必須）                                                 |
| 5   | `links`                 | 任意。最大 **10** 件。各 `url` は `http:`/`https:` 必須。`label` 任意（最大 100）                |
| 6   | `links` 空配列          | **許可**                                                                                         |
| 7   | `date`                  | 省略時は**サーバ当日（YYYY-MM-DD）**。指定時は `YYYY-MM-DD` のみ可                               |
| 8   | 同一日の複数投稿        | **許可**（1 日 1 件制約なし）                                                                    |
| 9   | `GET` クエリ            | `authorId` / `from` / `to` は任意。並びは **`date` 降順、同日は `createdAt` 降順**               |
| 10  | ヘッダー文言            | 新卒・トレーナーとも **「学び」**                                                                |
| 11  | body の Markdown        | 初版は**プレーンテキスト表示**（Markdown レンダリングは Phase 2）                                |
| 12  | 永続化                  | Firestore コレクション `learningPosts`（§9.5）                                                   |

### 画面・導線

| 項目         | 内容                                                                           |
| ------------ | ------------------------------------------------------------------------------ |
| ヘッダー文言 | 「学び」                                                                       |
| タイムライン | `/learnings`（新卒・トレーナー）。カード一覧（日付・タイトル・本文・リンク）   |
| 投稿画面     | `/learnings/new`（新卒のみ到達を想定。トレーナーは投稿 UI なしまたは遷移不可） |
| 投稿後       | 成功フィードバックのうえ `/learnings` に新投稿が表示される                     |

### 入力項目定義（§7.7.3）

| 内部キー   | 画面表示名 | 型 / 制約                                          |
| ---------- | ---------- | -------------------------------------------------- |
| `title`    | タイトル   | string 必須、1〜100 文字                           |
| `body`     | 学んだ内容 | string 必須、1〜2000 文字                          |
| `date`     | 投稿日     | `YYYY-MM-DD`（省略時サーバ当日）                   |
| `links`    | 参考リンク | `{ url, label? }[]`、0〜10 件                      |
| `authorId` | 投稿者     | サーバが認証ユーザから設定（クライアント指定不可） |

### 業務ルール

| ルール ID | 内容                                                                 |
| --------- | -------------------------------------------------------------------- |
| BR-L01    | 新卒は学び + リンクを投稿できる（UC-L01）                            |
| BR-L02    | 新卒・トレーナーはタイムラインを日付順で閲覧できる（UC-L02）         |
| BR-L03    | 永続化先は Firestore `learningPosts`                                 |
| BR-L04    | API は `GET/POST /api/learnings` を初版提供（PUT/DELETE は Phase 2） |
| BR-L05    | ヘッダー「学び」からタイムラインへ遷移できる                         |
| BR-L06    | 本機能の自動化対象テストが CI で Pass する                           |

### API エンドポイント（初版）

| メソッド | パス             | ロール           | 説明                                   |
| -------- | ---------------- | ---------------- | -------------------------------------- |
| GET      | `/api/learnings` | trainee, trainer | タイムライン（`?authorId=&from=&to=`） |
| POST     | `/api/learnings` | trainee          | 学び投稿（201）。トレーナーは 403      |

## ※確認事項

仕様・詳細設計から読み取れず、上記「実装既定」で仮置きした／未確定の点。

1. トレーナーのタイムラインは**全投稿**か、**担当新卒のみ**か（既定: 全投稿取得可）
2. `date` を未来日・過去日にどこまで許すか（既定: 形式が正しければ許可）
3. `label` 未指定時の UI 表示（既定: hostname または URL 文字列）
4. 投稿成功後の遷移先はタイムライン固定でよいか（既定: `/learnings`）
5. 新卒が他著者の投稿を見られる範囲（既定: フィルタなし時は一覧全体）
6. UI 全体のビジュアルを zip デザイン（ライト + 青プライマリ）へ寄せる範囲（既定: グローバル CSS トークンを置換し既存画面にも適用）
7. zip 内のカリキュラム／振り返り／タグ／ステータス UI を初版に含めるか（既定: **含めない**。学び投稿・タイムラインのみ）
