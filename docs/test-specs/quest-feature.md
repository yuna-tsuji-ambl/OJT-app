# クエスト（目標）管理機能 テスト仕様書

## 概要

スプレッドシートの育成計画（OJT計画書）と連動し、新卒がタスクのクリア申請を行い、OJTトレーナーが承認する機能。

OJTトレーナーはダッシュボード画面上部のクエスト作成機能から新しいクエストを追加できる。追加されたクエストは、トレーナー・新卒のどちらでログインしても一覧表示される。新卒はそのクエストに対してクリア申請ができ、トレーナーは申請状況を確認し、申請中のものを承認できる。申請済み・承認済みのクエストも、双方の一覧画面に表示される。

### UI仕様（表示ラベル・入力方式）

| データ項目（内部）               | 画面表示名 | 入力・表示方式                                                                   |
| -------------------------------- | ---------- | -------------------------------------------------------------------------------- |
| 大項目（`majorItem`）            | タイトル   | テキスト入力                                                                     |
| 小項目（`minorItem`）            | コメント   | テキスト入力                                                                     |
| 到達レベル（`achievementLevel`） | 到達レベル | ドロップダウンで数値（1〜5 等）を選択し、一覧では「Lv〇」（例: `Lv3`）形式で表示 |

クエスト作成フォームは、各項目を横並びではなく縦並びで配置する。入力部分のデザインは、新卒ホーム画面（`/home`）の送信部分（テンプレート選択・送信ボタン周辺）と同様のスタイルとする。

## F-01 ギャップ解消: SheetRepository 廃止と AssignmentRepository 移行

### 対象・参照

| 完了条件     | `SheetRepository` 依存の除去／一覧・申請・承認の Firestore 経由化／本節テストの実装 |

### 移行方針（テスト観点）

- 課題マスタの読み書きは `SheetRepository` ではなく **`AssignmentRepository`（Firestore `assignments` コレクション）** を正とする。
- 申請・承認のステータス遷移（§7.1.2）は既存の `QuestStatus` を流用する。
- 実装完了後、サービス層・ルート層から `SheetRepository` 型の引数・モックを除去する。
- API は §8.6.1 の `/api/assignments` 系を正とする（移行期間中の `/api/quests` 互換は実装判断に委ねるが、本節テストは `/api/assignments` を前提とする）。
