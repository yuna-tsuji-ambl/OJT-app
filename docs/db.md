# DB / 永続化定義（グランドルール）

コレクション一覧の正は [`docs/detailed-design.md`](./detailed-design.md) §9.5。  
本書は ID・null・正規化の解釈を定義する。

## 採用ストア

- 確定: Firestore（Emulator 可）
- PostgreSQL 案（§9.4）は参考。新規実装は Firestore 前提

## ID の振り方

| 方針            | 内容                                              |
| --------------- | ------------------------------------------------- |
| 生成場所        | サーバ（`crypto.randomUUID()`）を基本             |
| ドキュメント ID | コレクションごとに §9.5（`auto` / `{userId}` 等） |
| 禁止            | クライアント任意 ID の無検証受け入れ              |

## null 許容の基準

| 種類           | 基準                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| 必須           | 欠落・（仕様上）空文字不可 → 400                                           |
| 任意           | 省略可。永続化時に未設定をどう持つかはリソースごとに固定                   |
| 空文字 vs null | 原則「空文字は未入力として拒否、または trim 後空は未設定」。機能仕様で明示 |

## 正規化の考え方（Firestore）

- 厳密な RDB 正規化は求めない
- 参照整合が必要な関係は、許容する冗長と更新責務を機能仕様に書く
- 一覧用の非正規化フィールドを足す場合は更新経路を一つにまとめる

## 命名

- コレクション: §9.5 の名前を維持（camelCase）
- フィールド: camelCase
- リポジトリ外へ DB 固有型を漏らさない（ドメイン型へマッピング）
